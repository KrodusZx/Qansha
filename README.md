# Qansha? — интерактивный бюджет поездки, поиск недорогих рейсов и конкретных отелей

## Что уже реализовано

- Сохранён исходный калькулятор Qansha? с 51 направлением, сравнением и ползунком дневных расходов.
- Календарные поля вылета, возвращения, заезда и выезда из отеля, число гостей (до 9).
- Серверный запрос авиабилетов с обратным перелётом через **Google Flights (SerpApi)**.
- Запрос списка отелей и цен за указанные ночи через **Google Hotels (SerpApi)**.
- Названия конкретных отелей, варианты комнат, стоимость на компанию и на человека.
- Автоматические предложения «Эконом / Средний / Комфорт» из **найденных** отелей по рангу цены. Отели не выдумываются.
- Выбор рейса и отеля и пересчёт общего бюджета с ежедневными тратами.
- Избранное в браузере; после настройки Supabase — в аккаунте пользователя.
- Регистрация / вход по magic-link на email через Supabase Auth.

**Важное ограничение:** репозиторий — это готовый код интеграций, а не работающая система бронирования. Живой поиск не включится, пока владелец проекта не предоставит API-ключи и не развернёт серверные функции. Тестовая среда Amadeus может возвращать данные, не соответствующие реальной доступности/ценам. Кнопок покупки/оплаты билетов и отелей здесь нет. Для этого потребуется партнёрская/коммерческая интеграция и подтверждение условий поставщиков.

## Подключение дешёвых авиабилетов и отелей (SerpApi)

Qansha? 2.1 использует **Google Flights** и **Google Hotels** через SerpApi. Amadeus Self-Service закрыт; ключи Amadeus для этой версии больше не нужны.

1. Зарегистрируйтесь на https://serpapi.com/ и найдите приватный API Key в своём аккаунте.
2. В Vercel → qansha → Settings → Environment Variables создайте **зашифрованную** серверную переменную `SERPAPI_API_KEY` со значением ключа, для Production и Preview.
3. Выполните Redeploy последней публикации. Никогда не вставляйте API Key в `config.js`, `index.html` или публичный GitHub.
4. Проверьте страницу Qansha? и поиск, начиная с одного взрослого, будущих дат и большого города.

### Особенности честного сравнения цен

- Поиск авиабилетов делается **на точные даты** через два поисковых запроса Google Flights: отдельно туда и обратно. Для каждого направления берутся дешёвые варианты, комбинации сортируются по сумме. Это **два отдельных билета**, не один пакетный тариф туда-обратно; покупателю стоит проверить и единый round-trip у продавца.
- Google Flights ищет по **одному взрослому**; общая цена для группы — умножение на число путешественников, то есть ориентир, **не подтверждённая итоговая стоимость на группу**. Багаж обычно нужно уточнять отдельно.
- Поиск гостиниц показывает **конкретные названия и фотографии**, если их передал Google Hotels. Для нескольких номеров цена умножается на их число, но наличие нескольких одинаковых номеров не подтверждается. Внимательно проверьте итог с налогами и условия отмены.
- Это поисковая система, а не касса для оплаты. Сервис не утверждает, что нашёл абсолютно минимальный тариф среди всех существующих сайтов и авиакомпаний.
- Бесплатного тарифа SerpApi может хватить на немного поисков, потому что один поиск Qansha? включает три внешних запроса. Используйте лимиты и контроль расходования квоты в SerpApi.

## Включение регистрации и сохранения избранного

1. Создайте проект на [Supabase](https://supabase.com/).
2. В Dashboard → SQL Editor выполните `supabase/schema.sql`. Скрипт включает RLS: чужое избранное нельзя читать и изменять.
3. В Supabase → Authentication → Providers убедитесь, что разрешён Email / Magic Link.
4. В Authentication → URL Configuration добавьте ваш рабочий адрес Vercel в Site URL и Redirect URLs, чтобы ссылки входа работали.
5. В `config.js` укажите **публичные** `supabaseUrl` и `supabaseAnonKey` (или Publishable Key), найденные в Supabase Project Settings → API.
6. Переразверните сайт. Вход/регистрация выполняются через email. Без Supabase избранное сохраняется только в `localStorage` текущего браузера.

**Никогда не вставляйте service_role key Supabase или Amadeus API Secret в `config.js`, HTML или GitHub.**

## Проверка

```bash
npm test
```

Серверный поиск проверяет IATA-коды, даты и число пассажиров, а запросы отправляются через Amadeus OAuth. Отели подбираются с учётом двухместного размещения (`roomQuantity = ceil(travelers/2)`). Для нечётных групп цены могут соответствовать размещению с незанятой кроватью: пересчитайте состав гостей перед покупкой.

## Пояснения для туристов

- Онлайн-цена — это предложение в момент поиска. Оно не удерживает место и не гарантирует цену в момент покупки.
- Amadeus Flight Offers Search не охватывает абсолютно все авиакомпании/low-cost; сравнивайте результаты и с другими поставщиками.
- Данные и фотографии конкретных отелей зависят от партнёра. В текущей версии показываются название, адрес (если доступен), описание номера и общая цена; фотографии не включены.
- Статические карточки «Три готовых бюджета», цены продуктов и курс валют остаются **планировочными оценками**, а не онлайн-предложениями. Точные выбранные отель и рейс учитываются в отдельном блоке итоговой онлайн-сметы.
- Для гостя избранное хранится в этом браузере. Для вошедшего в аккаунт — в Supabase; автоматического слияния старых гостевых записей пока нет.
- Сохраняется цена на момент добавления в избранное, но она может устареть. Запрашивайте предложение заново перед оплатой.
